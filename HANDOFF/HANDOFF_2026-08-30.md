## Mobile: „WebGL context lost" (Pixel, Chrome Android) — Fix 2026-08-31

Symptom (Inhaber-Screenshot): Viewer leer mit Chromes „broken canvas"-Icon oben
links, UI darunter intakt — der WebGL-Kontext wurde vom Browser verworfen
(GPU-Speicher). Drei Änderungen (Build `e2b6a7c3` / NL `f1c2d8e4`):
1. `_scheduleARPrep()` läuft NICHT mehr bei jeder Konfigurationsänderung — vorher
   wurde auf Handys nach jedem Klick ein GLTF-Export + Upload gestartet (Haupt-
   verdächtiger). Nur ein Warm-up 8 s nach dem ersten Laden; sonst beim AR-Tipp.
2. `_releaseModelGPU()`: beim Formwechsel werden die Geometrie-Puffer des alten
   Modells freigegeben (vorher blieben alle je besuchten Formen auf der GPU,
   ~25 MB pro Form). Daten bleiben im JS-Cache, Rückwechsel lädt nur neu hoch.
3. `_installContextLossGuard()`: bei `webglcontextlost` Mini-Loader zeigen;
   three.js stellt bei `webglcontextrestored` selbst wieder her; kommt binnen
   4 s keine Wiederherstellung → einmaliges `location.reload()` (Zustand steht
   komplett in der URL), Loop-Schutz 90 s via sessionStorage.
Außerdem Shadow-Map auf Handys 1024² statt 2048². Getestet headless mit
Pixel-UA: Geometrien auf der GPU bleiben konstant (10) über 6 Formwechsel,
keine AR-Uploads nach Konfig-Änderungen, simulierter Context-Loss →
Restore bzw. Reload mit identischem Zustand (`/tmp`-Skripte ctxtest*.js).

## Stolperfalle Shopify-Admin über den Browser des Inhabers (2026-08-31)

Wenn beim Aufruf von admin.shopify.com jedes Mal „Choose an account" erscheint
(zwei Konten im Browser), hat der Admin keine gültige Session: die Seite rendert,
aber jede Interaktion (Menü, Modal, Tippen) friert den Tab minutenlang ein und
XHRs liefern 403. Lösung: Inhaber loggt sich einmal frisch als Nisar Derbaj ein
(accounts.shopify.com/store-login) — danach läuft alles normal. Die Formular-
felder des Admins liegen in Shadow-DOM (querySelector findet sie nicht; für
JS-Zugriff shadowRoot rekursiv durchlaufen). Produktbild ohne Datei-Dialog
(DataTransfer/Drop auf das Input funktioniert NICHT): Bild irgendwo per HTTPS
hosten (z. B. im Repo unter `configurator/Swatches/Product renders/`, wird von
Railway ausgeliefert) → im Produkt „Select existing" → „Add media" ▾ →
„Add media from URL" → URL einfügen → Add file → Done → Save.
